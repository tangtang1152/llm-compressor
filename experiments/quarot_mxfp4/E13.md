# E1.3 Raw weight and group-flat gamma control

Independent entry point: e13.py. Original E1/E1.2 code and results are unchanged.
CPU, selected weights only, default layers 3/6/16/40, exactly three historical
experts each, gate/up only. No down weights are loaded (shared preflight validates
selected expert triplet headers). No E0 expansion, activation QDQ, E2, or full
forward. Five QDQs per matrix, 24 matrices / 120 stage rows for the default scope.
No group detail files or plots.

|Stage|Reference weight for its own QDQ error|
|---|---|
|A|Original BF16 weight|
|B|Original gamma fusion, FP32 arithmetic, BF16 write-back|
|C|B followed by actual Hidden B32 executor, FP32, BF16 write-back|
|D|Group-flat gamma fusion, FP32 arithmetic, BF16 write-back|
|E|D followed by the same Hidden B32 executor|

Group-flat gamma is calculated from original BF16 values promoted to FP32:
r_g=sqrt(mean(gamma_g^2)) for each consecutive 32 input channels. Each nonzero
entry keeps its original sign and gets magnitude r_g. Zero entries (including
negative zero) receive +r_g; an entirely zero group remains zero. This achieves
uniform magnitude and preserves group RMS within FP32 rounding. Flat gamma stays
FP32 until fusion, avoiding an extra BF16 gamma-rounding step. Both original and
flat fusion use the actual fuse_norm_linears through core.transform. Gamma CSV
records negative/zero counts, all-zero groups and RMS preservation error. Replacing
zero gamma entries with nonzero values is an additional intervention; inspect its
count before attributing everything to nonuniform nonzero magnitudes.

D/E deliberately alter gamma and hence the function of a model using it. A/B/C
also have different weight representations. Every NMSE uses its own stage's
unquantized weight denominator. Cross-stage NMSE measures relative quantization
difficulty, not a common-target output reconstruction error. No Expert W4A4
accuracy claim is supported by E1.3 alone.

## Historical selection and validation

--reuse-e1 accepts original E1 results.json and newer E1.2 diagnostics.json with
full configuration/provenance. The adapter only normalizes e1_rows to rows before
calling existing strict reuse validation; original source bytes are hashed.
Older E1.2 files without index hash/rotation/quantization fields must use their
original E1 JSON inputs. Config/index, versions, quantizer source hashes, complete
historical triplets and fixed rotation must match. Git commit/source path may differ.
B/C are measured once each for this experiment and checked against historical NMSE
(rtol 1e-6, atol 1e-12), rather than blindly accepting incompatible historical rows.

Exactly three distinct historical IDs are required per requested layer. There is
no fallback sampling and no automatic first-three choice. If supplied history has
16 or multiple selections, pass --expert-selection /path/to/selection.json with
layer keys and the intended three historical IDs per layer. Each must already be
present in validated history. Use the actual old selection record; do not choose
based on observed error. Both resolved IDs and selection file hash are recorded.

## Server command

After publishing/synchronizing the new commit normally, run from the repository
root in the historical Python environment. Substitute real historical JSON paths.
Do not upgrade quantizer dependencies or overwrite any old output directory.

```bash
export PYTHONPATH="$PWD/src${PYTHONPATH:+:$PYTHONPATH}"
prior=(/absolute/path/to/history/results.json /absolute/path/to/other/history/results.json)
run=/mnt/share/t50065065/results/quarot/e13-$(date +%Y%m%d-%H%M%S)
/usr/bin/time -v python -m experiments.quarot_mxfp4.e13 \
  --checkpoint /mnt/weight/GLM-5.2 --reuse-e1 "${prior[@]}" \
  --layers 3 6 16 40 --threads 4 --output "$run" >"${run}.log" 2>&1
# Add --expert-selection /path/to/historical-three-expert-selection.json if needed.
python -c 'import json,sys; r=json.load(open(sys.argv[1])); assert r["status"]=="complete"; assert len(r["rows"])==120; assert len(r["paired"])==24; print(r["selection"],r["gamma"])' "$run/results.json"
```

Check RAM and disk availability before execution. Weight/group temporaries are
limited to the current matrix; expect CPU working memory on the order of the E1.2
single-matrix path, with extra BF16 references held by the variant generator.
Allow 4 GiB free RAM as an initial allowance; this is not a measured E1.3 server
peak. No checkpoint-sized allocation, no full group archive. Only scalar summaries
are retained across matrices. Real checkpoint I/O, elapsed time and RSS remain
unverified. Fresh output directory is mandatory. Failure writes failed status;
kill/power loss leaves running status, neither is a valid completed experiment.

## Results

- results.json: status, actual imported provenance, source hashes, config, selected
  experts, gamma policy, all measurements and comparisons.
- matrices.csv: every expert/projection/stage Weight NMSE, Group Max/RMS mean and
  P50/P95/P99, QDQ zero fraction, Block Relative MSE P95, matrix AbsMax/RMS.
- comparisons.csv: per-matrix B-A NMSE increase, relative B/A increase, C/A gain,
  B-D NMSE reduction, D/B gain, C/B gain, E/D gain and rotation-gain drop in pp.
- layers.csv / layer_comparisons.csv: arithmetic means over three experts,
  separately by layer and gate/up. This is not a pooled energy-weighted ratio.
- gamma.csv: sign/zero policy diagnostics and group RMS preservation error.
- summary.md: answers to the four paired comparisons by layer/projection.

Gain(reference,candidate)=100*(reference-candidate)/reference. Positive B/A increase
means fusion made relative weight error larger; positive C/A or D/B gain means
lower relative error. Positive (C/B gain - E/D gain) means flattening reduced the
rotation advantage. Zero baseline denominators produce null/NA, not infinity.
Three experts/layer provide descriptive patterns, not a significance test. Layer
consistency and effect size must be judged from real measurements; local synthetic
checks establish correctness only.

## Validation

Synthetic four-layer, three-expert fixture checks 120 stage rows, 24 paired rows,
40 layer-stage summaries and 8 layer-projection comparisons; original history is
byte-identical after the run. Tests also cover gamma RMS/sign/zero behavior,
B/C equality to actual production transform primitives, constant-magnitude gamma
B=D and C=E, comparison signs/zero denominators, ambiguous/missing selections,
E1.2 schema normalization, incompatible old schema, historical NMSE mismatch,
failed status and non-overwrite behavior. No synthetic analysis charts are created.

Validation result (2026-11-05): 3 focused tests passed in 9.82 s; Ruff passed.
The end-to-end synthetic test produced 120 stage records and verified all B/C
history checks, without generating plots. Real GLM-5.2 measurements were not run.
